## 一、先说结论：静态托管的保护上限

本仓库是**纯静态站点**。GitHub Pages 不提供任何服务端运行环境（没有后端、没有数据库、没有鉴权中间件）。因此：

| 你以为能做的 | 实际情况 |
|---|---|
| 在后端做访问控制 | ❌ GitHub Pages 无后端，无处实施 |
| 防止别人复制内容 | ❌ HTML/CSS/JS 与全部数据都会明文下发到浏览器，F12 或「保存网页」即可取得 |
| 防止别人拿去训练 AI | ⚠️ 只能靠 robots.txt 与 meta 声明**表达拒绝**，对方不遵守则无效 |
| 防止别人镜像托管 | ❌ 技术上做不到，只能事后主张著作权 |

**一句话：只要页面能被看到，内容就能被复制。** 任何声称能在纯静态页面上「锁住」数据的方法，本质上都只是提高门槛，不是阻止。真正能阻止的只有两条路——**不发布**，或者**发布的是精简/脱敏版本**。

## 二、本仓库实际做了哪些防护

### 1. 法律层（真正的追责依据）

| 文件/位置 | 作用 |
|---|---|
| `LICENSE` | 保留所有权利，逐条列明受保护内容、禁止行为（复制/转载/镜像/商用/AI 训练/移除声明）、允许行为（转链接/注明出处引用） |
| 页面 `<meta name="copyright">` `rights` `dcterms.rights` | 机器可读的版权声明 |
| 页面页脚版权块 | 人可见的完整授权条款摘要 |

法律层是**唯一具备实际约束力**的一层。它的前提是你能证明「这是我的作品」——见下一节。

### 2. 溯源层（解决「如何证明是我做的」）

- **指纹 `HX-CLB-WORK-20260921-A215F0AB`** 由「原始数据集 + 汇率 + 统一口径」的 SHA-256 前 8 位派生。数据集只要改动一个数字，指纹即变——所以它同时是**内容完整性校验值**。
- 指纹出现在三处：HTML 头部注释、页脚可见的琥珀色高亮块、以及全部配套文件。
- 复制整页 HTML 会带走头部注释与页脚指纹；复制可见文本会带走页脚指纹（它是**纯文本**，不是图片或 CSS 伪元素）。
- 由此可主张：任何与本指纹一致的版本都源于本仓库；指纹被刻意移除的版本，恰好证明移除者明知来源。

### 3. 反爬层（提高采集成本）

- `robots.txt`：全站 `Disallow: /`，并**逐条列出** 40+ 个目标（通用搜索引擎、AI 训练爬虫 GPTBot/ClaudeBot/CCBot/Google-Extended/Applebot-Extended/Bytespider/PerplexityBot 等、SEO 数据中介、网页归档站）。
- 页面 meta：`noindex, nofollow, noarchive, nosnippet, noimageindex, notranslate, noai, noimageai`，并对 googlebot / bingbot 单独声明。
- 效果：守规矩的爬虫会遵守。**不守规矩的不会。**

### 4. 页面加固层

- `Content-Security-Policy`：`default-src 'none'` 起手，只放行内联 style/script，`connect-src`/`frame-src`/`object-src`/`form-action` 全部关闭 → 任何人无法在本页注入外部资源或把你的页面套进他的 iframe 里冒充。
- `X-Content-Type-Options: nosniff`、`referrer: no-referrer`（不外泄访问来源）。
- 页面**零外部请求**（无 CDN、无字体、无统计脚本），因此不存在通过第三方资源泄露访问数据的通道。
- `@media print` 浅色适配：**存成 PDF 时版权块与指纹一并保留**，堵住「打印再转发」这条最省事的搬运路径。

### 5. 边缘层（推荐部署到 Cloudflare Pages，使本层真正生效）

`_headers` 文件已备好（Cloudflare Pages / Netlify 约定）。**注意：GitHub Pages 会忽略它**，那些响应头就只停留在 `<meta>` 层面，防护力大打折扣。

**本项目推荐部署到 Cloudflare Pages**（详见 README「部署要求」），原因之一就是 `_headers` 会在那里真正生效：

- `Content-Security-Policy`、`X-Frame-Options: DENY`、`Referrer-Policy` 由响应头下发（比 `<meta>` 强，`<meta>` 无法设置 `frame-ancestors`）
- `X-Robots-Tag: noindex, noai, noimageai` 由响应头下发，覆盖面大于页面 meta
- 后续还可叠加：WAF 速率限制（同一 IP 高频抓取直接拦）、Bot Fight Mode、对异常来源的 JS Challenge、隐藏源站

这也是静态站**唯一**能真正加访问门槛的路径 —— 若要更强的控制，只能改用带鉴权的托管（见下一节）。

## 三、如果你需要「真正的保护」

按强度从高到低，请任选一条，我可以直接实施：

1. **不公开数据**（最强）：只公开方法论与结论，把逐档价格表从页面剥离，改为私有文档。别人拿不到数据，结论也无法被直接商用。
2. **加访问门**：改用支持鉴权的托管（Cloudflare Access 邮箱白名单 / Vercel + 密码 / 自建服务），链接只发给指定的人。GitHub Pages 做不到这一步。
3. **边缘质询 + 时效轮换**：保留公开页但挂 Cloudflare，配合「数据只做趋势定性、不写具体金额」的呈现方式，让搬运失去价值。
4. **保持现状**：公开全量数据 + 完整法律声明 + 溯源指纹。适合「希望被引用、但不想被冒充」的场景。

## 四、发现侵权怎么办

1. 先固定证据：对侵权页面截图（含 URL 与时间）、`curl` 保存页面源码、确认其中的溯源指纹。
2. 若托管在 GitHub：提交 DMCA Takedown Notice，本仓库的 `LICENSE` 与指纹时间戳即为权利证明。
3. 若托管在境内平台：走平台投诉通道，附本许可文件与采集时间证据。
4. 商用侵权：保留追责权利，建议先发律师函固定对方明知状态。
